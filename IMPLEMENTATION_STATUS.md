## Decisions and constraints

- Preserve the local single-server architecture, one fixed stock unit per SKU, cash/QR declared payments, owner-approved full reversals, and existing weighted-average SKU costing. Lot tracking is an explicit owner product setting; product name, type, and tax class never infer it.
- Existing stock has no trustworthy lot identity. Migration preserves its quantity, value, and historical events as unallocated; an owner must record a physically verified reconciliation before tracked units can sell. Unknown batch/expiry values are never fabricated.
- Virtual bundles are offers only and have no independent physical stock or acquisition cost. Bundle promotion allocations remain separate from statutory discount snapshots.
- BNPC is a distinct, owner-controlled policy and feature switch that defaults off. Local weekly records do not know external-channel purchases and must not be represented as a nationwide allowance guarantee.
- Checkout requires an open cashier shift per the roadmap's sale-finalization sequence. Opening cash, closing count, variance reason, and shift close are implemented with checkout; reversal cash movements and their effect on shift reconciliation remain in bundle 4.
- Foundation account defaults: Argon2id hashes, 8-character minimum passwords, 30-minute idle and 12-hour absolute session expiry, strict same-site secure cookies, self-deactivation blocked, and first owner provisioned by a one-time CLI. These are documented and reversible before live use.
- Tax classes/rate, statutory benefit treatment details and rounding examples, supplier-cost basis, invoicing/registration and privacy approvals remain owner/professional decisions before live use. The owner must record an accountant-approved tax and cost policy before any live sale can finalize; without it the server blocks finalization. The checkout settings UI records that approval attestation and reference.
- Nearest-₱0.25 cash-total rounding is optional and off by default; it leaves QR totals and line tax unchanged, and saves a signed adjustment on sales and reversals. The report lists this separately from line revenue and estimated gross profit. The owner/accountant must approve the exact cash-rounding treatment before enabling it for live sales.
- The inventory screen labels estimates provisional until an approved tax and cost policy is recorded; afterward it uses the approved VAT inclusion and rounding settings and still labels gross profit as an estimate that excludes benefit discounts and operating costs. Zero-rated products remain blocked unless the approved setting allows them.
- CSV product import is optional in the roadmap and is deferred until catalog size justifies it; manual owner entry is available. Any later importer must enforce owner authorization and preview row errors before confirmation.
- Store OS, local address/network, planned client browsers/devices, backup destination, and physical certificate trust require confirmation/testing before the release gates that depend on them.
- Node.js 24 LTS is the roadmap target. The current workspace reports Node.js 26.10.0, outside the package's `>=24 <25` engine range; Node 24 is not available on PATH and no Node version manager is installed. F6 checks passed under Node 26.10.0, but the full check set and live preflight must be rerun under Node 24 before release.
- Bundle 5 decisions: reversals and cash events appear on their Manila calendar date; current stock/value is clearly labeled current beside the selected day's activity; store name and stable UUID are saved in settings and each manifest. Backup base paths are absolute and outside the repository/database; Medtryx separates development, test, and live packages in environment-specific subdirectories. Live requires a restricted customer-key file, loopback Express, secure cookies, and a distinct secondary filesystem identifier. Physical storage separation still needs owner verification.
- Restore requires current owner reauthentication and typing the manifest's store name, checks the chosen copy's hashes/integrity/customer ciphertexts/schema/owner, creates and verifies a two-copy safety backup, then replaces all operational tables atomically and revokes all sessions. A restore into a different environment is rejected. A configured key file is updated atomically to the package key; without a key file, restore only accepts a key matching the current environment key.
